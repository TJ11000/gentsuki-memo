# 原付の不調を「店に渡す症状のメモ」にする係

作ったのは Claude。渡したのは僕——原付で通勤する会社員、副業で配達、非エンジニア。

Claude Code 用の md 一式です。原付（市区町村ナンバーの原付一種・二種）の不調を本人の言葉で書くと、足りない所を最大 3 問だけ聞いて、バイク屋に渡せる **症状のメモ 1 枚**（A5）を返します。原因を 1 つに決めません。手順書は書きません。渡す所で終わる係です。

用語: **線を書いた人**＝この md の判断基準を口述した一人（僕）。**止まる語**＝聞くのをやめて「乗らずに店へ」を出す症状。**白紙の監査**＝経緯を渡していない別の Claude による点検。

## こういう時に

- セルを押したらいつもと違う音がする。店に行く前に、何をどう伝えればいいか分からない時に
- 配達の途中でパンクした。今日あと 2 時間走るのか、ここで止めるのか、ほかの人の線を一つ見たい時に
- 検索すると「原因は〇〇」と断定する記事が多くて、自分の症状と照らし合わせにくい時に

## 入れると起こること（実物の前後・同じ入力）

入力（線を書いた人の実話・`examples/00` と `examples/01` で同じ文）:

> クロスカブ110（JA45）、ピンクナンバー。先月くらいから、セルボタン押したら「ガキッ」て感じの音がして、それからセルがいつもと違う音でちゃんと回らんようになった。キックならかかる。走行は45,000kmくらい。あと、半年くらい前から走ってる時に異音がしてて、走れるから放置してた。

**前**（この md を置かない素の Claude Code・Opus 5.5・2026-11-03・1 本目・差し替えなし・全文は `examples/00_baseline_bare_claude_ja45.md`）

> セルの症状は、**スタータークラッチ（ワンウェイクラッチ）かスターター減速ギアの破損**がいちばん怪しいです。
> （中略）
> 1. **スタータークラッチの摩耗や破損**

原因を 1 つに決め、修理代の目安まで言い、聞くのは答えた後。

**後**（この md を置いた Claude Code・同じ日・白紙の監査 2 巡を反映した後の 3 本目・差し替えなし・全文は `examples/01_ja45_starter_noise.md`）

> セルの件と走行中の異音の件、それぞれ店に渡すのに足りないところを、1回だけ聞かせてください。分からない・見ていない、で大丈夫です。
> 1. **セルの今の音と、「ガキッ」の出方**：「ガキッ」は最初の1回だけでしたか、今も押すたびに鳴りますか。今のセルはどんな音で回りますか（例：「ウィーンと空回りする感じ」「ガリガリ引っかかる感じ」。違えば自分の言葉で）。
> 2. **走っている時の異音の音と、出る場面**：どんな音で、どんな時に出ますか（例：「加速中にゴロゴロ」「スピードに合わせてシャーッ」。違えば自分の言葉で）。

答えを返すと、紙が 1 枚出ます。各行に出所の札（`[本人の申告]` `[本人の観測: いつ・何回]` `[本人の推測]` `[AI の推測]` `[AI の知識・店で確認]` `[線を書いた人: 線／出典]` の 6 種、空欄は `[本人 未回答]` `[本人: 分からん]`）が付き、「店で見てもらう所の候補」は系統名と本人の言葉で止まり、「線を書いた人の線ではこうなる」が 1 つ、「分からん所」が残ります。

**効かなかった版（同じ日・直す前の走行。版の差は git の履歴と `examples/_audit_log.md`）**

- 配達中のスローパンク（`examples/04`）: 1 本目は「空気が抜ける」を止まる語に入れていて、聞かずに止まった。線を書いた人の実際の線（配達中はキットで直して今日を乗り切る）と衝突していた。2 本目は「今日は自分で応急」と 1 つに決めていて、乗ってよいかを係が決める形だった。3 本目で「乗り続けるなら／乗らないなら」の 2 行にし、決めるのは本人に戻した。
- JA45 セル（`examples/01`）: 1 本目は「店で見てもらう所の候補」が部品名まで絞っていて、診断の帯に半歩入っていた。白紙の監査で刺され、「系統名: 本人の症状の言葉」だけに直した。

## 使い方

1. このフォルダを Claude Code で開く（`CLAUDE.md` が流れを持っています）。
2. 症状を自由文で書く。`core/sheet.md` の「入口」の欄が目安。空欄があっても進みます。
3. 最大 3 問 返ってくる。分からない所は「分からん」でいい。
4. 紙が 1 枚出る。スクショか印刷で店へ。

ターミナルから（1 回目で問い、2 回目で紙）:

```bash
claude -p --setting-sources project < symptom.txt
claude -p --setting-sources project --continue < answers.txt
```

## 帽子を替えると別の現場の係になる

```
core/   芯＝聞き方・札・止まり方。帽子を替えても変わらない
hats/   帽子＝対象の範囲・線引き・当てにならない申告・部品の入口・その車種でよくある例（出典つき）
        genki_nishu.md … 原付一種・二種（今回の 1 枚）
        _TEMPLATE.md   … 空の帽子。ここを埋めると別の現場の係になる
examples/ 実例（入出力・無編集）と監査の記録
```

帽子に書くのは「知識」ではなく「どこで止まるか・どの申告が当てにならないか・1 日で閉じるか」だけ。整備の一般知識はモデルに任せ、そこから出た行には `[AI の知識・店で確認]` の札を付けます。

## なぜ止まるか

このハッカソンの運営は、禁止例の線を「人が最後に判断する（HITL）」「事実確認ができる」「責任が人に残る」と説明しています。この係の形で問題ないかを運営に確認し、事実確認ができる機能があれば問題ない、との返事を得ています（2026-11-02・適合の確認であって推奨ではありません）。

係はそれを紙の形で持ちます。

- 原因の判定と「今この車両に乗ってよいか」の判定は、本人と店。係はしない。紙の先頭にそう書く。
- 乗ると怪我する側の症状（ブレーキ・燃料漏れ・火や煙・ハンドル・裂けたタイヤ）が出た時点で聞くのをやめ、紙の先頭に「乗らずに店へ」を置く（`examples/02`）。
- 推測は `[AI の推測]`、一般知識は `[AI の知識・店で確認]`。本人の言葉と分けて残す。店が行ごとに裏を取れる。
- 乗り続けるかが絡む場面は、1 つに決めず「乗り続けるなら／乗らないなら」の 2 行で書く（`examples/04`）。
- 分からない所は「分からん所」として残す。埋めない。

## どう作ったか

1. 線を書いた人が、自分で直した／店に出した実例を口述（10 月末・約 60 発言）。
2. そこから「線」だけを抜いた（1 日で閉じるか・工具代≒工賃か・夏は出す・走れる不調は束ねる・簡単な物から順）。知識は抜かない。
3. 芯・帽子・紙の型を md で書き、実話 1 本で動かした。
4. 白紙の監査を 2 巡（指摘は `examples/_audit_log.md`）。直すたびに同じ入力で取り直した。
5. 実例を 5 本（前 1・当たり前に動く 1・止まる 1・対象の外 1・応急 1）。効かなかった版は上に残した。

同じ作り方の記録: https://github.com/TJ11000/persona-ab-factory

## 限界（as-of 2026-11-03）

- 帽子の線は一人の線です。万人向けの推奨ではなく、紙にもそう書きます。
- 試したのは Opus 5.5・`claude -p`・n は各 1〜3 本。版が変わると紙の中身は変わります。実例 01 では、本人の答えの一部を係が読み落として未回答扱いにした行があります（直さず残しています）。
- 紙の正しさは係が保証しません。店が行ごとに裏を取れる形にしてあるだけです。
- 126cc 以上・車・2 スト旧車は「今回の対象に入っていない」と断って時系列だけ返します（`examples/03`）。
- 「よくある例」は公開の出典 1 件＋線を書いた人の実例 1 件がそろった車種だけ（今は JA45 の 1 件）。
- 部品番号を引く入口は各メーカーの公式ページを指すだけで、中身は複製していません。

## English (5 lines)

A Claude Code project (Markdown only) that turns a moped owner's rough description of trouble into a one-page "symptom sheet" to hand to a repair shop. It asks at most three questions, does not settle on a cause, tags each line in the core sections with its source (owner said / owner observed / owner guessed / AI guess / AI knowledge, shop to verify / the line-writer's rule), and stops with "don't ride, go to the shop" when a safety-related symptom appears. The judgment rules come from one person's real repair-or-outsource decisions, kept separate from general mechanical knowledge so the model can be swapped. Replace `hats/` and the same core becomes a sheet-maker for a different trade. Built and iterated with Claude Code during Built with Claude: Japan 2026.
