# 原付の不調を「店に渡す症状のメモ」にする係

作ったのは Claude。判断の基準を口で話して作らせたのは僕——原付で通勤する会社員、副業で配達、非エンジニア。

Claude Code に置いて使う設定ファイル（md）一式です。原付（市区町村ナンバーの原付一種・二種。2 スト旧車を除く）の不調をふつうの言葉で書くと、足りない所を最大 3 問だけ聞いて、バイク屋に渡せる **症状のメモ 1 枚**（A5 くらい）を返します。原因を 1 つに決めません。手順書は書きません。店に渡したら、そこでおしまいです。

用語（この文書で繰り返す 3 つだけ）: **基準を決めた人**＝判断の基準を口で話した一人（僕）。**やめる症状**＝そこで聞くのをやめて「乗らずに店へ」を出す症状。**事情を知らない Claude の点検**＝経緯を教えていない別の Claude に読ませて点検したこと。

## こういう時に

- セルを押したらいつもと違う音がする。店に行く前に、何をどう伝えればいいか分からない時に
- 配達の途中でパンクした。今日あと 2 時間走るのか、ここで止めるのか、ほかの人の基準を一つ見たい時に（整備を店に任せる人には「乗らずに店へ」しか返りません。自分でタイヤ交換まで する人にだけ、応急の 2 行が出ます）
- 検索すると「原因は〇〇」と断定する記事が多くて、自分の症状と照らし合わせにくい時に

**うまくいかなかった前の版（同じ日・直す前の回。出力が残っている版はこのリポジトリの変更履歴に、指摘は `examples/_audit_log.md` に）**

## 使い方（入口は 2 つ・中身は同じ md）

**A. Claude Code**
1. このフォルダを Claude Code で開く（`CLAUDE.md` が流れを持っています）。
2. 症状をふつうの言葉で書いて送る。`core/sheet.md` の「入口」の欄が目安。空欄があっても進みます。
3. 最大 3 問 返ってくる。分からない所は「分からん」でいい。
4. 紙が 1 枚出る。スクショか印刷で店へ。

**B. claude.ai の Project（スマホのアプリ・ブラウザどちらでも）**
1. Project を 1 つ作り、「指示」欄に `project_paste.md`（4 枚をつなげた物）を貼る。
2. あとは A の 2〜4 と同じ。写真（登録証は名前と住所を指で隠して・メーター）はこちらの方が送りやすい。紙を PDF にしたい時はブラウザの印刷で（この md は PDF を作りません）。
3. 無料プランでも Project は作れます（上限 5 つ。claude.com/pricing の比較表と Anthropic のヘルプ記事・2026-11-05 時点）。使える回数はプランで変わります。

特別な追加機能は入れていません。どちらの入口も、ファイルを置く（貼る）だけで動きます。B は 2026-11-05 に試走 1 本（`examples/05` と同じ入力で 3 問→「乗らずに店へ」の紙。札が 1 か所 `[本人の観測]`／`[本人の推測]` で揺れた）。

実例（`examples/`）のやり直しに使ったコマンド（同じ症状文で前後を比べる用・使い方ではありません）:

```bash
claude -p --setting-sources project < symptom.txt
claude -p --setting-sources project --continue < answers.txt
```

## 車種ごとの部分を替えると、別の乗り物・別の現場に使える

```
core/   共通部分＝聞き方・タグ・やめどき。車種ごとの部分を替えても変わらない
hats/   車種ごとの部分（中では「帽子」と呼んでいます）＝対象の範囲・基準・当てにならない申告・部品の入口・その車種で報告のある例（出典つき）
        genki_nishu.md … 原付一種・二種（今回の 1 枚）
        _TEMPLATE.md   … 空の帽子。ここを埋めると別の現場用になる
examples/ 実例（症状文と出力・手を加えていない）と点検の記録
```

車種ごとの部分に書くのは主に基準（どこでやめるか・どの申告が当てにならないか・その日のうちに終わるか）と、本人が自分で引ける部品番号の入口、出典つきの報告例。整備の一般知識は書かず、モデルに任せます。そこから出た行には `[AI の知識・店で確認]` のタグを付けます。

## どこでやめるか、なぜか

このハッカソンの運営は、参加者向けの案内（非公開）で、禁止例との境目を「人が最後に判断すること」「事実確認ができること」「責任が人に残ること」と説明していました（要約・逐語ではありません）。このメモ作りの形が禁止例に当たらないかは、運営の質問窓口で聞いてあります（2026-11-02・内容は非公開のやり取り・ルールに合うかを聞いただけで、お墨付きをもらったわけではありません）。

このメモの形に、それを入れてあります。

- 原因の決めつけと「今この車両に乗ってよいか」の判断は、本人と店。メモ作りはしない。メモの先頭にそう書く。
- ケガにつながりやすい症状（ブレーキ・燃料漏れ・火や煙・ハンドル・裂けたタイヤ。整備を店に任せる人にはパンクも）が出た時点で聞くのをやめ、メモの先頭に「乗らずに店へ」を置く（`examples/02`）。
- 推測は `[AI の推測]`、一般知識は `[AI の知識・店で確認]`。本人の言葉と区別する。店が 1 行ずつ確かめられる。
- 修理代や部品代の金額を書かない。部品代だけ先に知って店に行くと、工賃や開けてから出てくる想定外の部品で揉める種になる（基準を決めた人が車の受付側にいた時の実感）。メモに書くのは「店で聞く事: 見積り・部品が出るか・直さない選択があるか」まで。
- 乗り続けるかが絡む場面で、本人が自分でタイヤ交換まで する人なら、1 つに決めず「乗り続けるなら／乗らないなら」の 2 行で書く（`examples/04`）。
- 分からない所は「分からん所」として残す。埋めない。

## どう作ったか

1. 基準を決めた人が、自分で直した／店に出した実例を口で話した（10 月末・やりとり約 60 回）。
2. そこから基準だけを抜き出した（その日のうちに終わるか・工具代が工賃と同じくらいなら店か・夏は店に出す・走れる不調はまとめて出す・簡単な物から順）。知識は抜かない。
3. 共通部分・車種ごとの部分・メモの型をファイルで書き、実話 1 つで動かした。
4. 事情を知らない Claude に 2 回点検させた（指摘は `examples/_audit_log.md`）。直すたびに同じ症状文でやり直した。
5. 実例は 8 つ（置く前／ふつうに動いた／途中でやめた／対象外／応急／整備の知識が無い人の言い方で 3 つ）。うまくいかなかった前の版は上に残した。
6. 基準を直したあとは、知識の無い人の言い方 15 本（`examples/_persona_test_bank.md`）の最初の 1 往復を全部回して、基準から引いた期待と合うかを表で見た（2026-11-05・13／15 が期待どおり・外れた 2 本は両方「安全側に止まった」側。1 本は基準に 1 行足した）。

同じ作り方をした別の記録: https://github.com/TJ11000/persona-ab-factory

### 道具を足さなかった理由（Skills・MCP・フック・サブエージェントを使っていません）

候補に挙げて外した物と、外した理由です。「選ばなかった」も選び方のうち、と思って書いています。

- 地図の MCP（現在地から最寄りのバイク屋を出す）: 店を選ぶ責任がメモに乗る。メモはどの店にも渡せる物にした。店探しはスマホの地図で足りる。
- 写真を読む専用の道具: 入口に「登録証とメーターの写真でもよい」と書くだけで、Claude Code 側がそのまま読めた（`examples/_persona_test_bank.md` #1・#7）。
- 止まる症状を機械で判定するフック: 「乗ると怪我する側か」は言葉の揺れが大きく、固定の語リストだと「キーって音」（ブレーキかもしれない）を拾えない。モデルの一般知識に判断させ、迷えば止まる側に倒す、と文で書いた方が外さなかった（15 本中 13 本が期待どおり・外れた 2 本は両方 止まる側）。
- サブエージェント: 流れが 3 段（書く→3 問→紙）で、分ける所が無い。

入れるならここ: 整備を自分でする段の人向けの車種ごとの部分（`hats/`）を作るなら、部品表から部品番号と価格を引くスキル（基準を決めた人が自分の車種用に別に持っている物）を付けるのが合います。基準を決めた人自身はそれを使っていますが、公開にあたって読者を整備の知識が無い人まで広げるために、意図して外しました（その帽子は未作成・未試走）。

残ったのは md 3 枚です。同じモデルに、同じ症状文を渡して、前提のファイルがあるかないかで出力の形が変わった（上の「置くとこう変わる」）。賢いモデルほど前提側が効くかどうかは、1 つのモデルでしか試していないので分かりません。

## 限界（as-of 2026-11-05）

- 基準は一人の基準です。みんなに当てはまる答えではないので、メモにもそう書いてあります。
- 基準を決めた人自身は、この道具を使っていません。自分の車種の部品表を読ませて、原因を推測で相談し、部品代の概算まで出す使い方をしています（整備を自分でする段の人の使い方）。この道具はそこから「原因を決めない・金額を言わない」側に切り出した、整備の知識が無い人向けの物です。段の高い人向けは、車種ごとの部分（`hats/`）を替えれば作れる見込みですが、まだ作っていません。
- 試したのは Opus 5.5・2026-11-03〜05・`claude -p`・試した回数は各 1〜7 回（前後の例は「置く前」が 11/5 の 1 回目、「置いた後」が 7 回目・どちらも差し替えなし）。同じ入力でも回ごとに揺れます（例: `examples/04` は 4 回目だけ問いを出さずに紙を出した）。版が変わるとメモの中身は変わります。
- 答えが全部「分からない」だと、メモは時系列と「撮る物」のリストだけになります（整備の知識が無い人ほどそうなります）。それでも店に渡せる物にはなりますが、薄い。だから車両の欄が埋まらない時は、メモの先頭に「店に行く前に撮る 2 枚」を置くようにしました（2026-11-05 夜に足した線・実例 07 はその前の回）。
- 止まる側は保守側に振ってあります（ブレーキが「キーキー鳴る」だけでも、効きが分からなければ「乗らずに店へ」で止まります）。厳しすぎると感じる人もいると思います。
- 普通のチャットに毎回「原因を決めずに、店に渡すメモにして」と頼めば、近い物は出ると思います。この md は、その頼み方と、止まる症状・出どころのタグ・一人の基準を、毎回同じにしておく物です。それ以上ではありません。
- メモの正しさは保証できません。店が 1 行ずつ確かめられる形にしてあるだけです。
- 126cc 以上・車・2 スト旧車は「今回の対象に入っていない」と断って、いつから何が起きたかの整理だけ返します（試したのは 126cc 以上の 1 回＝`examples/03`。車・2 スト旧車は試していません）。
- 店向けの「報告例」は、公開の出典 1 件＋基準を決めた人の実例 1 件がそろった車種だけ（今は JA45 の 1 件・2 件しかないので「よくある」とは書きません。出典の記事には型式の記載がなく、年式から JA45 と判断しています。メモの中では出典 URL が日付のページまでに短くなります）。
- 部品番号を調べる入口は各メーカーの公式ページを指すだけで、中身はコピーしていません。

## English (5 lines)

A Claude Code project (Markdown only) that turns a moped owner's rough description of trouble into a one-page "symptom sheet" to hand to a repair shop. It asks at most three questions, does not settle on a cause, tags each line in the core sections with its source (owner said / owner observed / owner guessed / AI guess / AI knowledge, shop to verify / the rule-setter's judgment), and stops with "don't ride, go to the shop" when a safety-related symptom appears. The judgment rules come from one person's real repair-or-outsource decisions, kept separate from general mechanical knowledge so the model can be swapped. Replace `hats/` and the same core becomes a sheet-maker for a different trade. Built and iterated with Claude Code during Built with Claude: Japan 2026.
