# 原付の不調を「店に渡す症状のメモ」にする係

作ったのは Claude。渡したのは僕——原付で通勤する会社員、副業で配達、非エンジニア。

Claude Code 用の md 一式です。原付（市区町村ナンバーの原付一種・二種）の不調を本人の言葉で書くと、足りない所を最大 3 問だけ聞いて、バイク屋に渡せる **症状のメモ 1 枚**（A5）を返します。原因は当てません。直し方も言いません。渡す所で終わる係です。

## こういう時に

- セルを押したらいつもと違う音がする。店に行く前に、何をどう伝えればいいか分からない時に
- 配達の途中でパンクした。今日あと 2 時間走るのか、ここで止めるのか、自分の線が欲しい時に
- 検索すると「原因は〇〇」と断定する記事ばかりで、自分の症状と照らし合わせられない時に

## 入れると起こること（実物の前後）

**前**（素の Claude Code・Opus 5.5・この md なし・2026-11-02 計測・同じ問い）

> 原付のセルが回らなくなった。キックならかかる。何が原因？部品交換したい。

> → むやみに部品を替える前に、次の順番で切り分けると無駄な出費を防げます。（中略・原因の表と安い順の点検 6 段）…車種と症状を教えてもらえれば、もう少し絞り込めます。

車種を聞くのは答えた後。「店へ」の出口なし。部品交換を押し返したのは良い。

**後**（この md を置いた Claude Code・同じ日・`examples/01_ja45_starter_noise.md`・走行 1 本目・差し替えなし）

> クロスカブ110（JA45）、ピンクナンバー。先月くらいから、セルボタン押したら「ガキッ」て感じの音がして…キックならかかる。

> → 1枚にする前に、店に渡すのに足りん所を3つだけ聞かせてください。聞くのはこの1回だけです。「分からん」「見てへん」もそのまま答えになります。
> 1. 半年前からの走ってる時の異音は、どんな時に、どんな音がする？ …

答えを返すと、紙が 1 枚出ます。各行に出所の札（`[本人の申告]` `[本人の観測: いつ・何回]` `[AI の推測]` `[AI の知識・店で確認]` …）が付き、「店で見てもらう所の候補」は系統（電気・駆動…）までで止まり、「どうするか」は線を書いた人の線で 1 つ、「分からん所」が残ります。全文は `examples/01` に無編集で置いています。

**効かなかった実測（同じ日）**

- 配達中のスローパンク（`examples/04`）: 最初の版は「空気が抜ける」を止まる語に入れていたので、聞かずに「乗らずに店へ」で止まった。線を書いた人の実際の線（配達中はキットで直して今日を乗り切る）と衝突していた。止まる語を「裂け・バースト・ホイールの曲がり」に絞って直した。
- JA45 セル（`examples/01` の最初の版）: 「店で見てもらう所の候補」が部品名まで絞り込んでいて、診断の帯に半歩入っていた。白紙の監査で刺され、「系統まで・最大 2 行」に直した。

## 使い方

1. このフォルダを Claude Code で開く（`CLAUDE.md` が流れを持っています）。
2. 症状を自由文で書く。`core/sheet.md` の「入口」の欄が目安。空欄があっても進みます。
3. 最大 3 問 返ってくる。分からない所は「分からん」でいい。
4. 紙が 1 枚出る。スクショか印刷で店へ。

ターミナルからなら:

```bash
claude -p --setting-sources project < symptom.txt
```

## ヘルメットを帽子に替える

```
core/   芯＝聞き方・札・止まり方。帽子を替えても変わらない
hats/   帽子＝射程・線引き・当てにならない申告・部品の入口・その車種でよくある例（出典つき）
        genki_nishu.md … 原付一種・二種（今回の 1 枚）
        _TEMPLATE.md   … 空の帽子。ここを埋めると別の現場の係になる
examples/ 実例（入出力・無編集）
```

線は「知識」ではなく「どこで止まるか・どの申告が当てにならないか・1 日で閉じるか」だけを帽子に書きます。整備の一般知識はモデルに任せ、そこから出た行には `[AI の知識・店で確認]` の札を付けます。

## なぜ止まるか

このハッカソンの運営の線は「HITL（人が最後に判断する）」「事実確認ができる」「責任が人に残る」です。確認した時の運営の返事（2026-11-02）: 「はい、大丈夫です。事実確認ができるような機能が付いていれば大丈夫です。」

係はそれを紙の形で持ちます。

- 原因の判定と「今この車両に乗ってよいか」の判定は、本人と店。係はしない。
- 乗ると怪我する側の症状（ブレーキ・燃料漏れ・火や煙・ハンドル・裂けたタイヤ）が出た時点で聞くのをやめ、紙の先頭に「乗らずに店へ」を置く。
- 推測は `[AI の推測]`、一般知識は `[AI の知識・店で確認]`。本人の言葉と分けて残す。店が行ごとに裏を取れる。
- 分からない所は「分からん所」として残す。埋めない。

## どう作ったか

1. 線を書いた人が、自分で直した／店に出した実例を口述（10 月末・約 60 発言）。
2. そこから「線」だけを抜いた（1 日で閉じるか・工具代≒工賃か・夏は出す・走れる不調は束ねる・簡単な物から順）。知識は抜かない。
3. 芯・帽子・紙の型を md で書き、実話 1 本で動かした。
4. 文脈を持たない監査（白紙）に 1 巡かけて MAJOR 6 を直し、もう一度動かした。
5. 実例を 4 本（当たり前に動く 1・止まる 1・射程の外 1・応急 1）。効かなかった版は上に残した。

同じ作り方の記録: https://github.com/TJ11000/persona-ab-factory

## 限界（as-of 2026-11-03）

- 帽子の線は一人の線です。万人向けの推奨ではなく、紙にもそう書きます。
- 試したのは Opus 5.5・`claude -p`・n は各 1〜2 本。版が変わると紙の中身は変わります。
- 紙の正しさは係が保証しません。店が行ごとに裏を取れる形にしてあるだけです。
- 126cc 以上・車・2 スト旧車は「今回は入れてへん」と断って時系列だけ返します。
- 部品番号を引く入口は各メーカーの公式ページを指すだけで、中身は複製していません。

## English (5 lines)

A Claude Code project (Markdown only) that turns a moped owner's rough description of trouble into a one-page "symptom sheet" to hand to a repair shop. It asks at most three questions, never names a cause, tags every line with its source (`[owner said]`, `[owner observed]`, `[AI guess]`, `[AI knowledge, shop to verify]`), and stops with "don't ride, go to the shop" when a safety-related symptom appears. The judgment lines come from one person's real repair-or-outsource decisions, kept separate from general mechanical knowledge so the model can be swapped. Replace `hats/` and the same core becomes a sheet-maker for a different trade. Built and iterated with Claude Code during Built with Claude: Japan 2026.
